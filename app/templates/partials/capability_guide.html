Capability guide

Three different things, kept apart: what this Forge app implements, what Factory documents as native platform capabilities, and what would be future work. Native capabilities are not implemented or configured by Forge, and Forge has not inspected any organization's Factory settings. Availability depends on the Factory plan and on how an organization configures it.

Implemented in Forge

Built and exercised in this app
  • Issue intake. A signed GitHub webhook or the Issues tab starts work, only for repositories in FORGE_ALLOWED_REPOSITORIES.
  • Local Droid SDK turns. Each turn runs in its own workspace clone with a credential-free remote and a clean agent environment. One paid turn runs at a time, runtime and continuation limits apply, stop is durable, and a restart never resumes work on its own.
  • Per-attempt accounting. Every turn is an attempt with its own status and Factory credits as reported by the SDK. Failed and retried work stays in totals; dollars stay unknown unless you record an estimate or a reconciled amount.
  • Evidence on the exact commit. App-run acceptance checks in a clean checkout and a restricted Read/Grep/Glob review of the exact diff, both bound to the candidate SHA.
  • Explicit approval and publication. You approve one SHA; a separate, policy-gated step pushes it without force to an allowed branch and opens a draft pull request. Remote CI is observed read-only. Forge never merges.
  • PR review assignment by number, including drafts, with the AI verdict kept apart from what GitHub recorded.
  • Outcome economics and evidence export. Accepted changes, observed credits, dollar coverage, user-entered effort and assumptions, and a bounded JSON export of one selected task.

Boundary. Forge is a private, single-operator console with one operator token and in-memory sessions, meant for loopback use. Agents run as the same OS account as the app: this is a trusted workload, not a sandbox, and not multi-user access control, SSO or a hosted service.

Future extension

Not built
  • Multi-user access with SSO and roles instead of one operator token.
  • A billing source for reconciling dollars automatically, instead of manual estimates and reconciled amounts.
  • Separate usage attribution for delegated child sessions, which the SDK does not report to Forge today.
  • Running agents in an isolated sandbox or on remote compute rather than as the app's OS account.
  • A durable job queue and a shared database for more than one app instance.
  • Exporting Forge outcomes to an organization's analytics or telemetry pipeline.
